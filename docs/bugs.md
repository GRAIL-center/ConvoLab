## Fixed

| # | Found | Bug | Impact | Fix |
|---|-------|-----|--------|-----|
| F16 | 2026-08-18 | Study conversation window was too short: 7-min soft cap / 8-min hard stop, and the survey unlocked only on a 6-turn count, so a slower participant could be auto-redirected before finishing a real exchange | Conversations were cut off before participants had said what they wanted; the "wrapping up soon" banner fired at 5:30 | Soft cap 8 min, hard stop 12 min. The soft cap is now an unlock rather than a deadline: at 8 min the survey opens regardless of turn count, the participant may keep going to 12 min, and the wrap-up warning moved to 90s before the hard stop. Voluntary finishes always record `participant_finish` (was `soft_cap` after the cap, which conflated choice with enforcement). Stale `?? 8` fallback for `minParticipantTurns` corrected to 6 |
| F17 | 2026-08-18 | The export-coverage guard scanned only `study.ts`, but the WebSocket layer also writes study fields onto sessions, so `studyConversationStartedAt` was written and never exported without failing anything | The exact seam failure the guard was built to prevent — an unexported study field invisible to CI | Guard now scans `ws/conversation.ts` as well; `studyConversationStartedAt` exported as `conversation_started_at`. Verified the widened guard genuinely fails by removing the exporter row and watching it go red naming the field |
| F14 | 2026-08-18 | Participant's own message rendered twice: the optimistic echo uses `id: Date.now()` (a number) while the server id is a Firestore string, so they can never match. `score:update` normally rewrites the optimistic id, but if a reconnect replays history first it bailed with `return prev` and left the twin on screen | Visible transcript corruption in the pilot — the participant sees their message duplicated, one copy carrying the provisional tone border and one unscored | Optimistic messages now carry `isOptimistic`; the history merge dedupes them against server copies by content with a count-aware multiset (so a genuinely repeated turn survives), and `score:update` drops the stale twin instead of bailing |
| F15 | 2026-08-18 | The two populist personas never stated their gender in the second person — only third-person "She believes..." — so the model fell back on masculine-default idiom. Live pilot: Megan Briggs said "Guys like me". The shared coach prompt is written in generic "they/their", so the coach called Megan "they" | Partner gender is a randomised study factor; the manipulation was weakened by the partner misgendering itself and the coach neutralising it | `withSelfReference()` appends an explicit second-person gender/pronoun block to all four study personas (idiom warning only on the woman personas, so the male register is not asymmetrically flattened); `buildStudyCoachPrompt()` injects the partner's name and pronouns into the per-session coach prompt |
| F12 | 2026-08-18 | Study session timer restarted on every page load: `elapsedSeconds` counted from component mount and `StudyInfo` carried no server anchor | A participant who refreshed got a fresh 7-min soft cap and 8-min hard stop, so the conversation window was unenforceable and turn-count dosage drifted | Clock anchored server-side to first conversation connect and persisted as `studyConversationStartedAt`; API sends `elapsedSecondsAtConnect` (elapsed seconds, not a timestamp, so a skewed device clock cannot shift it) and the client adds its own delta. ## Process

- Log every bug here when found (one row: date, symptom, impact), even if fixed
  in the same commit — the log is the searchable history.
- Fix as we go: small, verified fixes commit directly to `main`; anything
  risky or behavior-changing gets flagged to the team first.
